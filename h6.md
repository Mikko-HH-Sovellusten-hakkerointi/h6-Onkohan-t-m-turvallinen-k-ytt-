## Tapo C200

Tässä tehtävässä on tarkoitus tutkia Tapo C200 -kameran firmwaren turvallisuutta ja selvittää siinä piilevät haavoittuvuudet. 

Aluksi ladataan GitHubista [tp-link-decrypt](https://github.com/robbins/tp-link-decrypt) -työkalu, jolla voidaan purkaa TP-Linkin laitteiden firmware-päivitystiedostojen suojaus (Robbins): 

```bash
# Asennetaan Git ja build-työkalut (Debian/Ubuntu)
sudo apt update
sudo apt install git build-essential make gcc
 
# Ladataan itse lähdekoodi
git clone https://github.com/robbins/tp-link-decrypt.git
cd tp-link-decrypt
 
# Asennettaan riippuvuudet (jos preinstall.sh löytyy)
chmod +x preinstall.sh
./preinstall.sh
 
# Käännetään ohjelma
make
```

Tämän jälkeen ladataan TapoV3 firmwaren binääri TP-Linkin julkisesta S3-bucketista:

```bash
aws s3 cp \
s3://download.tplinkcloud.com/firmware/Tapo_C200v3_en_1.4.2_Build_250313_Rel.40499n_up_boot-signed_1747894968535.bin \
firmware.bin \
--no-sign-request
```

Ajetaan ```~/tp-link-decrypt/bin/tp-link-decrypt firmware.bin``` -komento, jolla tp-link-decrypt -työkalu purkaa firmwaren salauksen. Tarkistetaan, että purku on onnistunut komennolla ```ls -lh```:

Tutkitaan löytyykö tiedostojärjestelmästä salasanoja tai salasanahasheja sisältäviä tiedostoja komennolla ```find squashfs-root -name passwd -o -name shadow```. Komento ei palauttanut mitään tuloksia. Puretusta SquashFS-tiedostojärjestelmästä ei myöskään löytynyt Linuxille tyypillisiä käyttäjätietokantatiedostoja, kuten passwd tai shadow. Lisäksi unsquashfs purki vain noin 70 tiedostoa, joten on todennäköistä, ettei tämä tiedostojärjestelmä sisällä laitteen koko käyttöjärjestelmää, vaan ainoastaan osan siitä. Tarvittaessa tähän voidaan palata myöhemmin ja tutkia tarkemmin esimerkiksi bin-hakemistosta löytyvää **main**-tiedostoa. Seuraavaksi siirrytään tutkimaan Moodlesta ladattua dump-tiedostoa.

Puretaan dump-tiedosto Binwalkilla komennolla ```binwalk -Me dump-tapo-c200v3-1.4.2.bin```, jonka jälkeen tarkastellaan purettua sisältöä. Dump-tiedostosta paljastui myös squashfs-root-hakemisto, aivan kuten aiemmin firmwarea purettaessa.

Googlaamalla merkkijonon **zMiVw8Kw0oxKXL0** selvisi, että kyseessä on TP-Linkin IP-kameroissa käytetty kovakoodattu salasana (National Vulnerability Database, 2018). Sama merkkijono löytyi myös Ghidralla useista root-käyttäjää käsittelevistä funktioista, mikä vahvisti, ettei kyse ollut satunnaisesta data-arvosta. Ohjelmasta löytyi lisäksi logiikka, joka korvasi kyseisen arvon toisella 64-merkkisellä heksadesimaalisella arvolla, mutta alkuperäinen salasana oli edelleen löydettävissä firmwaresta. Koska firmwaresta löytyi aiemmin myös admin-käyttäjä, on mahdollista, että kyseisen salasanan käyttäjätunnus on **admin**, mutta tätä ei voida varmistaa ilman fyysistä laitetta. CVE-kuvauksessa kovakoodatun salasanan kerrotaan löytyvän tiedostosta /usr/lib/lua/luci/websys.lua. Tässä työssä sama salasana löytyi kuitenkin myös Ghidralla analysoidusta main-binääristä, mikä viittaa siihen, että tunnistetta käytetään muuallakin kuin pelkässä web-käyttöliittymässä.

Löydös vaikutti entistä uskottavammalta, koska sama salasanaan liittyvä koodi löytyi myös toisesta firmware-versiosta. Tämän perusteella kyse ei vaikuta olevan yksittäisen version poikkeuksesta, vaan samankaltainen toteutus on ollut mukana useammassa ohjelmistoversiossa.
