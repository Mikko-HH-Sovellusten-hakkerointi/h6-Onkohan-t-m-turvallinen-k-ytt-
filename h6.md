## Tapo C200

Tässä tehtävässä on tarkoitus tutkia Tapo C200 -kameran firmwaren turvallisuutta 

Aluksi ladataan GitHubista [tp-link-decrypt](https://github.com/robbins/tp-link-decrypt) -työkalu, jolla voidaan purkaa TP-Linkin laitteiden firmware-päivitystiedostojen suojaus: 

```bash
# Asennetaan Git ja build-työkalut (Debian/Ubuntu)
sudo apt update
sudo apt install git build-essential make gcc
 
# Ladataan itse lähdekoodi
git clone https://github.com/robbins/tp-link-decrypt.git
cd tp-link-decrypt
 
# Asennettaan riippuvuudet (jos preinstall.sh löytyy)
chmod +x preinstall.sh
./preinstall.sh
 
# Käännetään ohjelma
make
```

Tämän jälkeen ladataan TapoV3 firmwaren binääri TP-Linkin julkisesta S3-bucketista:

```bash
aws s3 cp \
s3://download.tplinkcloud.com/firmware/Tapo_C200v3_en_1.4.2_Build_250313_Rel.40499n_up_boot-signed_1747894968535.bin \
firmware.bin \
--no-sign-request
```

Ajetaan ```~/tp-link-decrypt/bin/tp-link-decrypt firmware.bin``` -komento, jolla tp-link-decrypt -työkalu purkaa firmwaren salauksen. Tarkistetaan, että purku on onnistunut komennolla ```ls -lh```:

Tutkitaan, että löytyykö salasanoja ja/tai salasanahasheja sisältävää hakemistoa komennolla ```find squashfs-root -name passwd -o -name shadow```. Tämä ei palauttanut mitään. Muutenkaan puretusta SquashFS-tiedostojärjestelmästä ei löytynyt Linux-järjestelmille tyypillisiä käyttäjätietokantatiedostoja (passwd tai shadow). Ja koska unsquashfs purki vain noin 70 tiedostoa, niin tämän perusteella purettu tiedostojärjestelmä ei todennäköisesti sisällä laitteen koko käyttöjärjestelmää, vaan vain osan siitä. Tarvittaessa palataan tänne myöhemmin ja tutkitaan lisää esim. bin-hakemistossa olevaa maintiedostoa. Nyt kuitenkin tutkimaan Moodlesta ladattua dump-tiedostoa.

Puretaan dump-tiedosto taas binwalkilla komentoa ```binwalk -Me dump-tapo-c200v3-1.4.2.bin``` käyttämällä, jonka jälkeen listataan sen sisältö. Dump-tiedoston puretusta sisällöstä paljastui myös squashfs-root -kansio, aivan kuten firmwarenkin kanssa:
